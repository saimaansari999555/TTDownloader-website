

PHASE 4 – PART A

MASTER PROMPT (Complete Software Requirements Specification - SRS)

> Continue from all previous phases.

Do not generate application code yet.

Your task is to produce a complete Software Requirements Specification (SRS) for this CMS-based web application.

The SRS must follow professional software engineering standards (IEEE-style where appropriate) and be detailed enough that a development team could implement the application without guessing requirements.




---

DOCUMENT OBJECTIVE

Generate a complete software blueprint.

This document must become the single source of truth for the project.

No feature should be undocumented.

No assumption should be left unexplained.

FINAL QUALITY REQUIREMENTS

The SRS should:

Be internally consistent.

Avoid ambiguity.

Avoid contradictory requirements.

Use professional engineering language.

Be easy to maintain.

Be suitable for handoff to developers, QA engineers, UI/UX designers, DevOps engineers, and project managers.



---

⭐ Enterprise Requirements

Produce documentation that can support a multi-person development team.

Clearly separate mandatory requirements from future enhancements.

Ensure traceability between business goals, requirements, implementation, and testing.

Make the document suitable as the project's long-term technical reference.
